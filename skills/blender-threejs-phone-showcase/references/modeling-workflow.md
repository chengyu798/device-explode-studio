# 从参考资料到展示网页

## 资料和精度

明确机型、地区、SIM 分支、目标配色、整机/拆解用途和交付方式。先检查现有模型与文件，不清空用户场景。尺寸图优先于照片透视测量，实拆照片优先于概念拆解海报；分别记录标注尺寸、照片拟合和估算部分。涉及新机型或精确资料时读取原始来源并核对，不沿用 A3527 参数。

当前外观依据 Apple [iPhone 17 Pro Max 外形图](https://developer.apple.com/download/files/accessories/dimensional-drawings/iphone-17-pro-max.pdf)；内部依据[组件视图](https://support.apple.com/en-my/124264)、[pSIM 电池](https://support.apple.com/en-my/123387)、[主板](https://support.apple.com/en-my/123395)和[后摄](https://support.apple.com/en-my/123388)。这些是外形/维修参考，不是内部测量 CAD。

## 建模顺序与判断

先匹配机身比例、圆角、厚度、平台轮廓，再做背板、屏幕、镜头、传感器、侧控和底孔，最后添加内部组件。以正交正背侧底视图确认尺寸，以三分之四视图确认曲面与反射。连续机壳和平台应有真实过渡；用叠加盒子只能作为早期占位。

所有可拆组件挂到独立空节点，组件 ID 与网页元数据一致；建模完成再设展开偏移。估算内部布局要保证部件可辨识、装配不明显穿插。不要从概念海报照搬螺丝数量和电池形状。

按键先确认位置、座深、密封圈中心、外向面，再处理表面颜色。底孔必须切穿外壳，黑色贴片不能代替开口。布尔运算后检查非流形边和实际射线通道。射线证明孔中心打开还不够：需要扫描整个底部并核对间距、宽度，螺丝沉孔也要检查遮挡。

镜头应有空心金属镜筒、暗腔、盖片与示意透镜。实心柱体会挡住内部；过度光滑的平面法线会让盖片变成白色气泡。Logo 应有干净轮廓、正确背面朝向和足够微小的表面间距，避免反面剔除或深度冲突。

## Blender 与 Three.js

保留原生程序材质，在导出副本中用物理参数替代不支持的法线/粗糙度网络。配色按语义角色集中维护，不靠遍历所有材质统一染色。机身高光主要由倒角、曲面、粗糙度和反光板共同形成；不能仅用增亮颜色补救几何问题。

以本地打包的 Three.js、GLTFLoader、OrbitControls 运行，保留 MIT 许可。需要的新功能按项目版本文档实现。保留现有单面剔除策略，微小薄片才局部双面。GLB 不包含摄影棚和旧归档，但原生文件继续保留它们。

改另一机型时，适配 profile.json、model.js 的组件信息/边界/偏移、load-blender.js 的资源名与数量检查、视图取景、材质角色匹配、精度说明和校验坐标。默认模板不是模型无关的通用生成器。

## 操作持久性

改动前另存版本。MCP 先读取场景、对象与单位，不假设材质节点语言和 enum。不要在未保存的活跃场景回调中直接打开另一个文件；可用独立后台 Blender，或保存后通过延时回调打开。历史一次性修补脚本不能重复执行；本 skill 的复现路径直接使用最终种子。
